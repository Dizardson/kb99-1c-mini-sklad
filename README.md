![Мини-Склад](assets/banner.png)

**Учебная конфигурация для «1С:Предприятия 8.3»**, разработанная в рамках стажировки КБ99 «1С Старт с нуля».

Проект демонстрирует работу с документами и регистрами накопления, расчёт себестоимости по FIFO и автоматический пересчёт последующих реализаций при изменении документов задним числом, разграничение прав доступа и регламентные задания.

Отдельно в репозитории представлена внешняя печатная форма акта списания товаров для типовой конфигурации «Управление торговлей 11.5».

## Возможности

- Учёт поступлений и реализаций товаров.
- Автоматический расчёт суммы строки документа по количеству и цене.
- Формирование движений по регистрам остатков и оборотов.
- Учёт партий и списание по методу **FIFO** с расчётом себестоимости.
- Контроль доступного количества товара при проведении реализации.
- Автоматический пересчёт зависимых реализаций при проведении, изменении или отмене проведения документов задним числом.
- Отчёт «Обороты по товарам» на системе компоновки данных (СКД).
- Печатная форма документа «Реализация».
- Возможность подбора товаров и контрагентов непосредственно при заполнении документов.
- Проверка заполнения обязательных реквизитов перед проведением документов.
- Отображение складских остатков и условное оформление списка товаров.
- Разграничение прав доступа для разных категорий пользователей.
- Регламентное обновление и слияние индексов полнотекстового поиска.

## Регламентные задания

Для обслуживания полнотекстового поиска создан общий модуль `РегламентныеПроцедуры` и два регламентных задания:

- `ОбновлениеИндекса` — обновление индекса при его неактуальности.
- `СлияниеИндексов` — обновление индекса со слиянием его частей при его неактуальности.

Перед выполнением процедур проверяется, разрешён ли полнотекстовый поиск. Для задания обновления индекса задано ежедневное расписание с интервалом повторения 60 секунд.

## Как работает FIFO

**FIFO (First In, First Out)** — сначала списываются товары из наиболее ранних доступных партий поступления.

### Обычное списание

1. При проведении **Поступления** количество и стоимость записываются в регистр `ОстаткиТоваров`. Партией выступает ссылка на документ поступления.
2. При проведении **Реализации** подготавливается список товаров документа, после чего определяются доступные остатки по партиям на момент проведения.
3. Партии обрабатываются в порядке их поступления: сначала ранние, затем более поздние.
4. Если первой партии недостаточно, необходимое количество списывается из следующих партий.
5. Себестоимость определяется по стоимости списываемых остатков партий, отдельно от цены продажи.
6. Если доступного количества не хватает, проведение прерывается с сообщением о недостатке товара.

### Автоматический пересчет FIFO при изменении документов

При изменении ранее проведённых документов могут измениться остатки партий и себестоимость последующих реализаций. Чтобы сохранить корректность учёта, система автоматически пересчитывает затронутые документы в хронологическом порядке.

1. Перед изменением документа определяется **дата начала пересчёта**. При редактировании существующего документа учитывается и его прежняя дата.
2. Определяются затронутые товары, включая прежнюю номенклатуру при её изменении.
3. Находятся последующие проведённые реализации по этим товарам.
4. Их движения очищаются, затем реализации обрабатываются **в хронологическом порядке**, чтобы каждая следующая использовала актуальные остатки партий.
5. Внутренний признак пересчёта предотвращает повторный запуск той же цепочки при перепроведении зависимых документов.

Механизм вызывается при проведении и отмене проведения **Поступления** и **Реализации**.

## Внешняя печатная форма для УТ 11.5

В рамках пятой недели разработана внешняя печатная форма **«Акт списания товаров»** для документа `СписаниеНедостачТоваров` типовой конфигурации «Управление торговлей 11.5».

За основу взята типовая печатная форма, дополненная выводом причины списания из реквизита `Комментарий` документа. Сохранено формирование штрихкода, реквизитов организации, подразделения и склада, таблицы списываемых товаров, общего количества наименований и подписей ответственных лиц.

Обработка подключается через механизм дополнительных отчётов и обработок Библиотеки стандартных подсистем (БСП). Для её использования не требуется вносить изменения в типовую конфигурацию УТ.

В каталоге [`ВнешняяПечатнаяФорма`](ВнешняяПечатнаяФорма/) находятся готовый файл `.epf`, исходный код модуля объекта и XML-выгрузка макета.

## Установка и запуск

1. Установите платформу **«1С:Предприятие 8.3»** с доступом к Конфигуратору.
2. **[Скачайте репозиторий ZIP-архивом](https://github.com/Dizardson/kb99-1c-mini-sklad/archive/refs/heads/main.zip)** и распакуйте его в отдельную папку.
3. В окне запуска 1С выберите **Добавить → Создание новой информационной базы → Создание информационной базы без конфигурации**. Завершите создание базы.
4. Откройте новую базу в режиме **Конфигуратор** и выполните **Конфигурация → Открыть конфигурацию**.
5. В меню **Конфигурация → Загрузить конфигурацию из файлов…** укажите папку `МиниСклад` из скачанного репозитория.
6. После загрузки выполните **Конфигурация → Обновить конфигурацию базы данных** (`F7`) и подтвердите изменения.
7. Запустите **1С:Предприятие** (`F5`). Объекты конфигурации доступны через подсистему **«Мини-Склад»**.

> Для проверки используйте отдельную пустую базу. Репозиторий содержит исходные файлы конфигурации, а не заполненную демонстрационную информационную базу.

### Подключение внешней печатной формы

> Внешняя печатная форма предназначена для УТ 11.5, а не для учебной конфигурации «Мини-Склад».

1. Откройте информационную базу **«Управление торговлей 11.5»** в режиме 1С:Предприятие.
2. Перейдите в раздел **НСИ и администрирование → Печатные формы, отчёты и обработки** и включите использование дополнительных отчётов и обработок, если оно отключено.
3. Откройте список дополнительных отчётов и обработок, добавьте файл [`АктСписанияТоваров.epf`](ВнешняяПечатнаяФорма/АктСписанияТоваров.epf) и сохраните обработку.
4. Откройте документ «Списание недостач товаров», заполните его табличную часть и укажите причину списания в поле «Комментарий».
5. Запишите документ и выберите команду **Печать → Акт списания товаров(внешняя печатная форма)**.

## Этапы разработки

- **Неделя 1** — справочники, документы, формы и интерфейс.
- **Неделя 2** — регистры накопления, движения, отчёт СКД и печатная форма.
- **Неделя 3** — FIFO, себестоимость и автоматический пересчёт при изменениях задним числом.
- **Неделя 4** — формы подбора товаров и контрагентов, условное оформление списка, проверка заполнения реквизитов.
- **Неделя 5** — настройка ролей пользователей, регламентные задания полнотекстового поиска и внешняя печатная форма акта списания товаров для УТ 11.5.
