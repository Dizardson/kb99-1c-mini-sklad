![Мини-Склад](assets/banner.png)

**Учебная конфигурация для «1С:Предприятия 8.3»**, разработанная в рамках стажировки КБ99 «1С Старт с нуля».

Проект демонстрирует работу с документами и регистрами накопления, расчёт себестоимости по FIFO и автоматический пересчёт последующих реализаций при изменении документов задним числом.

## Возможности

- Учёт поступлений и реализаций товаров.
- Автоматический расчёт суммы строки документа по количеству и цене.
- Формирование движений по регистрам остатков и оборотов.
- Учёт партий и списание по методу **FIFO** с расчётом себестоимости.
- Контроль доступного количества товара при проведении реализации.
- Автоматический пересчёт зависимых реализаций при проведении, изменении или отмене проведения документов задним числом.
- Отчёт «Обороты по товарам» на системе компоновки данных (СКД).
- Печатная форма документа «Реализация».
- Возможность подбора товаров и контрагентов непосредственно при заполнении документов.
- Разграничение прав доступа для разных категорий пользователей.
- Многоскладской учёт: склады у поступлений и реализаций, отдельные остатки и обороты по складам.
- FIFO в разрезе складов, включая пересчёт затронутых реализаций при переносе проведённого документа с одного склада на другой.
- RLS по назначенным складам для Менеджера и Кладовщика.
- Синхронизация пользователей информационной базы со справочником `ПользователиИБ` по расписанию, с записью результата и ошибок в журнал регистрации.

## Разграничение прав доступа

В конфигурации созданы четыре роли:

| Роль | Назначение |
|---|---|
| **Администратор** | Администрирование и работа с основными объектами конфигурации |
| **Менеджер** | Ведение справочников и реализаций, просмотр поступлений, остатков и отчёта |
| **Кладовщик** | Оформление поступлений, просмотр реализаций, справочников и остатков |
| **Гость** | Просмотр товаров и остатков без редактирования |

### RLS по складам

В документах `Поступление` и `Реализация` предусмотрен реквизит `Склад`, а в регистрах накопления `ОстаткиТоваров` и `Обороты` — одноимённое измерение.

Для ролей **Менеджер** и **Кладовщик** ограничения доступа на уровне записей (RLS) используют склады, назначенные сотруднику в регистре сведений `РегистрНазначенийСкладов`. Текущий пользователь информационной базы сопоставляется с элементом справочника `ПользователиИБ` по UUID. Через параметр сеанса `ТекущийСотрудник` определяется сотрудник для проверки назначений складов.

Права ролей и ограничения на уровне записей проверялись в отдельных пользовательских сеансах. Роль **Гость** имеет права просмотра; RLS по назначенным складам для неё не настроено.

## Как работает FIFO

**FIFO (First In, First Out)** — сначала списываются товары из наиболее ранних доступных партий поступления.

### Обычное списание

1. При проведении **Поступления** количество и стоимость записываются в регистр `ОстаткиТоваров`. Партией выступает ссылка на документ поступления.
2. При проведении **Реализации** подготавливается список товаров документа, после чего определяются доступные остатки по партиям на момент проведения.
3. Партии обрабатываются в порядке их поступления: сначала ранние, затем более поздние.
4. Если первой партии недостаточно, необходимое количество списывается из следующих партий.
5. Себестоимость определяется по стоимости списываемых остатков партий, отдельно от цены продажи.
6. Если доступного количества не хватает, проведение прерывается с сообщением о недостатке товара.

### Автоматический пересчет FIFO при изменении документов

При изменении ранее проведенных документов могут измениться остатки партий и себестоимость последующих реализаций. Что бы сохранить корректность учета, система автоматически пересчитывает затронутые документы в хронологическом порядке.

1. Перед изменением документа определяется **дата начала пересчёта**. При редактировании существующего документа учитывается и его прежняя дата.
2. Определяются затронутые товары, включая прежнюю номенклатуру при её изменении.
3. Находятся последующие проведённые реализации по этим товарам.
4. Их движения очищаются, затем реализации обрабатываются **в хронологическом порядке**, чтобы каждая следующая использовала актуальные остатки партий.
5. Внутренний признак пересчёта предотвращает повторный запуск той же цепочки при перепроведении зависимых документов.

Механизм вызывается при проведении и отмене проведения **Поступления** и **Реализации**.

### FIFO при изменении склада документа

Списание происходит только из партий того склада, который указан в реализации. При поиске последующих реализаций для пересчёта используются затронутые товары и склад.

Если у ранее проведённого поступления или реализации изменяется склад, учитываются прежний и новый склады: перерасчёт выполняется по затронутым цепочкам FIFO на обоих складах. Это позволяет корректно перераспределить партии после переноса документа.

## Автоматическая синхронизация пользователей

Служебный справочник `ПользователиИБ` хранит прикладные записи пользователей информационной базы: имя, имя входа, уникальный идентификатор (UUID), статус синхронизации и дату последнего обновления.

Общий модуль `СинхронизацияПользователейИБ`:

1. Создаёт отсутствующие в справочнике записи пользователей информационной базы.
2. Обновляет полное имя, имя входа и статус при изменении данных пользователя.
3. Отмечает записи, для которых пользователь больше не найден в информационной базе, статусом `ОтсутствиеВИБ`.
4. Не перезаписывает элементы, если данные не изменились.
5. Записывает итоговые счётчики и сведения об ошибках в журнал регистрации.

Предопределённое регламентное задание `СинхронизацияПользователей` выполняет обновление по расписанию. В журнале регистрации проверены события запуска, итоговая статистика синхронизации и успешное завершение фонового задания.

Для ограничения доступа к складам после синхронизации пользователю назначаются склады через `РегистрНазначенийСкладов`.

## Установка и запуск

1. Установите платформу **«1С:Предприятие 8.3»** с доступом к Конфигуратору.
2. **[Скачайте репозиторий ZIP-архивом](https://github.com/Dizardson/kb99-1c-mini-sklad/archive/refs/heads/main.zip)** и распакуйте его в отдельную папку.
3. В окне запуска 1С выберите **Добавить → Создание новой информационной базы → Создание информационной базы без конфигурации**. Завершите создание базы.
4. Откройте новую базу в режиме **Конфигуратор** и выполните **Конфигурация → Открыть конфигурацию**.
5. В меню **Конфигурация → Загрузить конфигурацию из файлов…** укажите папку `МиниСклад` из скачанного репозитория.
6. После загрузки выполните **Конфигурация → Обновить конфигурацию базы данных** (`F7`) и подтвердите изменения.
7. Запустите **1С:Предприятие** (`F5`). Объекты конфигурации доступны через подсистему **«Мини-Склад»**.

## Внешняя печатная форма для УТ 11.5

В каталоге `ВнешняяПечатнаяФорма` находится **«Акт списания товаров»** для документа `СписаниеНедостачТоваров` конфигурации «Управление торговлей 11.5».

Обработка подключается через механизм дополнительных отчётов и обработок БСП. Печатная форма использует пакетный запрос, собственный MXL-макет и штатное формирование штрихкода документа. Поддерживается печать нескольких актов с размещением каждого на отдельной странице.

Для подключения добавьте `АктСписанияТоваров.epf` в список дополнительных отчётов и обработок УТ 11.5.

## Этапы разработки

- **Неделя 1** — справочники, документы, формы и интерфейс.
- **Неделя 2** — регистры накопления, движения, отчёт СКД и печатная форма.
- **Неделя 3** — FIFO, себестоимость и автоматический пересчёт при изменениях задним числом.
- **Неделя 4** — форма подбора товаров, условное оформление списка, проверка заполнения реквизитов.
- **Неделя 5** — роли и RLS по складам, многоскладской FIFO и пересчёт при смене склада, синхронизация пользователей по расписанию, внешняя печатная форма для УТ 11.5.
